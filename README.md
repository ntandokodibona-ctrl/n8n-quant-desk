# n8n Quant Desk

A self-hosted, multi-agent market analysis pipeline built in n8n. It pulls real
daily price data for five tickers, computes a fixed set of quantitative
metrics deterministically in code, hands those metrics to an LLM agent for
interpretation, passes that interpretation to a second LLM agent for
position sizing, and renders the result as one dated markdown report.

No live capital, no broker connection, no execution. This is an analysis and
risk-sizing tool, not a trading bot.

## What it does

On trigger, the workflow:

1. Generates a fixed list of five tickers (AAPL, MSFT, GOOGL, AMZN, NVDA).
2. Pulls 200 days of daily OHLCV data for each from Twelve Data's free tier.
3. Computes, in plain JavaScript (no LLM involved): period return,
   annualised volatility, price position relative to the 50-day and 200-day
   simple moving averages, a golden-cross flag, and max drawdown.
4. Sends those metrics to an **Analyst agent**, which writes a short
   bullish/bearish/neutral view per ticker with a 1-10 conviction score,
   grounded only in the numbers it's given.
5. Sends the Analyst's view, plus the same volatility and drawdown figures,
   to a **Risk agent**, which sizes a hypothetical position against a fixed
   $10,000 account and 1%-per-trade risk rule, sets a stop distance, and
   rejects trades below a conviction or volatility threshold.
6. Renders all five results into a single dated markdown report.

## Architecture

## Why metrics are computed in code, not by an LLM

Every number that goes into a trading decision here — returns, volatility,
moving averages, drawdown — is computed with plain arithmetic in a Code
node, not generated or estimated by a language model. The LLM agents only
ever *interpret* numbers they're handed; they never calculate them. This
was a deliberate design constraint, not a limitation: an LLM's job in this
pipeline is judgement, not arithmetic, and letting a model compute the
numbers it later reasons about would make the whole system's outputs
unverifiable.

## A build note worth knowing

n8n's AI Agent node returns only its own `output` field and drops every
other field that was on the item before it. This means the Analyst agent's
output loses access to the original metrics unless they're explicitly
re-joined afterward. The `Parse Analyst` node exists specifically to pull
the metrics back in from the `Compute Metrics` node by direct reference,
rather than assuming they survive the trip through the agent. This is the
kind of implicit behaviour that's easy to miss and produces silently wrong
downstream numbers if you don't account for it.

## Setup

1. Run n8n locally via Docker:
2. Import `workflow/quant-desk.json` into n8n.
3. Create a free [Twelve Data](https://twelvedata.com) account and API key.
4. Create a free [Groq](https://console.groq.com) account and API key.
5. Add both as credentials/values in the HTTP Request and Chat Model nodes.
6. Run the workflow manually from the trigger node.

## Roadmap

The original concept was a fuller "quant desk" with more specialised
agents. These were deliberately cut from this build to keep scope
realistic, and are listed here rather than half-built:

- **Chart / technical reading agent** — visual pattern recognition from
  price charts, not just numeric indicators.
- **ETF screening** — filtering a wider universe of tickers against
  criteria, not just analysing five fixed names.
- **Predictive modelling** — forward-looking forecasts, which would need
  real backtesting rigour before being trustworthy.
- **Execution agent** — connecting to a paper-trading broker API to
  actually place simulated orders.
- **Formal coordinator agent** — currently the workflow's own node
  sequence acts as the coordinator; a dedicated agent could route between
  a larger set of specialist agents dynamically.

## Limitations

- Free-tier data only (Twelve Data), rate-limited to roughly 8 requests/min.
- Account size and risk-per-trade are hardcoded, not configurable via input.
- Risk agent's position sizing logic has not been checked against a real
  broker's margin or lot-size rules — it is illustrative, not tradeable.
- No backtesting: the Analyst and Risk agents have not been evaluated
  against historical outcomes, only checked for coherent reasoning.
- Groq's free-tier model availability changes over time; the model ID
  pinned in this workflow may need updating if it's later deprecated.
